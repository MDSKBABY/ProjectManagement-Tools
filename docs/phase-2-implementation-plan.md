# 第二期连续开发计划：实施留痕与工作沉淀

> 执行方式：用户已确认按本计划连续实施。每个模块保持“测试先行 → 小步实现 → 独立验证 → 回归验证 → 进度记录”，模块之间不再等待人工确认；只有产品方向变化、需要新增外部服务或存在不可逆操作时暂停。

## 阶段目标

在已完成的统一工作项基础上，补齐技术知识、日报周报、厂商接口、会议培训、设计资料和项目全周期节点，让实施过程中的信息可以结构化保存、检索、确认和追溯。

## 统一约束

- 保持 Vue 3、TypeScript、Element Plus、Spring Boot、MyBatis-Flex 和 PostgreSQL，不更换技术栈。
- 保持服务端 Session Cookie + CSRF；所有项目资源继续叠加功能权限和项目成员权限。
- Flyway 只新增迁移，不修改 V1～V12。
- 草稿允许暂缺附件；正式提交或确认时执行附件、纪要等完整性校验。
- 日报和周报确认后不覆盖已确认内容；周报保存所用日报快照。
- Ollama 仅生成草稿；不可用或超时时不影响原始日报保存，并返回可理解的错误。
- 配置、模型名和服务地址使用环境变量，不在仓库保存密钥或生产地址。
- 不引入新的前端状态库或大型依赖；优先复用项目工作台、文件资产和统一错误处理。

## 模块顺序

### 模块 0：第二期基线验收（已完成）

- 后端全量测试与 JAR 打包。
- 前端全量测试与生产构建。
- 生产镜像构建、空库 Flyway V1～V12、初始化管理员和容器内部访问验证。

### 模块 1：技术知识库（已完成）

- 文章草稿、提交审核、通过和驳回状态。
- 场景、现象、原因、解决办法、适用条件、关键词和附件。
- 项目内组合检索、详情、修改、软删除和审计。

### 模块 2：日报基础（已完成）

- 原始工作内容、工时、关联工作项/会议/部署记录和确认状态。
- 草稿可修改，确认后内容不可覆盖。

### 模块 3：Ollama 日报润色（已完成）

- 可配置地址、模型和超时。
- AI 只返回润色草稿；调用失败不改变日报。

### 模块 4：周报与日报快照（已完成）

- 按项目和周期汇总已确认日报。
- 保存日报快照、周报草稿、下周计划、生成方式和确认状态。

### 模块 5：厂商与接口记录（已完成）

- 厂商档案、联系人和系统信息。
- 接口方向、协议、地址、鉴权方式、字段说明、推送频率和联调状态。
- 正式提交时至少存在一个可用附件。

### 模块 6：会议与培训（已完成）

- 例会、汇报、培训记录，参会人、纪要、待办和材料附件。
- 正式提交时纪要必填且至少存在一个可用附件。

### 模块 7：设计资料（已完成）

- 原型、埋点图、设计说明等类型，支持阶段、版本、外链、附件和关联需求。

### 模块 8：项目全周期节点（已完成）

- 汇总里程碑、部署、会议、日报周报等关键节点。
- 统一计算正常、临期和延期状态；时间边界由后端负责。

### 模块 9：第二期整体验收（已完成）

- 覆盖权限、状态机、附件强制校验、AI 失败降级、日报确认和周报快照。
- 执行前后端全量测试、生产构建、空库迁移和核心业务链路验收。

## 风险点

| 风险 | 处理方式 |
| --- | --- |
| AI 服务不稳定 | 独立调用边界、连接和读取超时、失败不写坏业务数据 |
| 已确认报告被覆盖 | 状态保护与数据库快照共同约束 |
| 附件跨项目引用 | 后端核对文件项目、状态和当前用户权限 |
| 模块过多导致回归范围扩大 | 每个模块独立迁移、独立 API 测试和前端组件测试 |
| 全周期节点查询变慢 | 先按项目和时间窗口聚合；不做无界全表查询 |
