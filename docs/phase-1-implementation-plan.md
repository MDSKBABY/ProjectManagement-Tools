# 第一期连续开发计划：项目基础与资料复用

> 执行方式：本计划一次确认后连续实施。每个模块仍保持“小步实现 → 独立测试 → 回归测试 → 进度记录”，但模块之间不再等待人工确认。只有产品方向变化、需要新增外部服务或存在不可逆操作时才暂停。

## 阶段目标

完成项目、成员、文件、部署资产、服务器、环境指纹、部署方案和部署记录的完整工作台。最终用户能够创建项目、上传版本化资料、维护服务器与环境、沉淀成功部署基线，并按相似环境检索历史方案。

## 统一技术和安全约束

- 保持 Vue 3 + TypeScript + Element Plus、Spring Boot + MyBatis-Flex + PostgreSQL，不更换技术栈。
- 继续使用服务端 Session Cookie 与 CSRF，不迁移到 JWT。
- 后端先定义稳定的 `/api/v1` 契约，前端类型与客户端紧随契约实现。
- 所有项目资源同时检查功能权限和项目成员关系；无查看权限时尽量以 404 隐藏资源存在性。
- 文件开发环境写入受控本地目录；文件名不能直接成为磁盘路径，下载必须重新授权。
- 服务器凭据只保存密文，默认响应永不返回密文或明文；解密查看单独授权并审计。
- Flyway 历史迁移保持不变，数据库变化只新增迁移。
- 不引入不必要依赖，不创建 Git 提交，除非用户另行要求。

## 交互演进约束

- 按 `ADR-001` 保留现有技术栈，使用 Vue 和 Element Plus 自主实现 Plane 风格的信息架构与交互。
- 第一期不引入 OpenProject 或 Plane 运行服务，不建立双系统数据同步。
- 优先形成“全局工作区 → 项目侧边栏 → 模块内容 → 详情面板”的导航层级，但不为了改外观破坏已稳定的 API 和权限边界。
- 模块 6～9 每次只在当前页面范围内完成交互改良；模块 10 再统一导航、页面布局、设计变量和空/加载/错误状态。
- 统一工作项属于第二期；第一期只保留可关联扩展的边界，不提前创建空洞抽象。

## 模块与依赖顺序

### 模块 1：项目管理后端最小闭环（已完成）

**成果：** 项目创建、分页查询、详情、更新、软删除、资源级授权与审计。

**验收：** 已通过 6 个项目 API 测试及 38 个后端全量测试。

### 模块 2：项目成员管理 API（已完成）

**范围：** 成员分页查询、添加、角色调整、移除和审计；`OWNER` 暂不通过普通成员接口转让。

**接口：**

- `GET /api/v1/projects/{projectId}/members`
- `GET /api/v1/projects/{projectId}/members/candidates`
- `POST /api/v1/projects/{projectId}/members`
- `PUT /api/v1/projects/{projectId}/members/{userId}`
- `DELETE /api/v1/projects/{projectId}/members/{userId}`

**验收：** 仅管理员、项目 `OWNER`/`MANAGER` 可管理；仅活动用户可加入；OWNER 不可修改或移除；重复添加冲突；重复移除幂等；全部写操作审计。

### 模块 3：项目工作台前端（已完成）

**范围：** 项目导航、列表筛选、创建表单、详情编辑、成员维护；用现有 Session/CSRF 客户端访问真实接口。

**验收：** 加载、空、错误状态完整；无权限操作不显示；关键表单和 API 客户端有测试；窄屏可用；`typecheck`、测试和构建通过。

**依赖：** 模块 1、2。

### 模块 4：统一文件元数据与本地存储（已完成）

**范围：** 新增文件资产、业务关联和存储配置；实现受控目录、元数据创建和项目文件列表；前端同步提供项目资料列表与上传入口骨架。

**验收：** 路径不可穿越；文件与项目权限绑定；元数据与物理文件状态一致；列表分页；本地存储目录通过环境变量配置。

**依赖：** 模块 3 的项目工作台框架。

### 模块 5：分片上传、校验、版本与下载鉴权（已完成）

**范围：** 初始化上传、分片写入、完成合并、SHA-256 校验、版本链、授权下载；前端实现进度、重试、取消和版本列表。

**验收：** 限制单文件最大 2GB；分片越界/重复安全处理；合并后校验哈希；资产版本不可覆盖；无项目权限不能上传或下载。

**依赖：** 模块 4。

### 模块 6：部署资产归档（已完成）

**范围：** 安装包、脚本、手册、配置模板和依赖组件的元数据、版本、筛选及文件关联；前端提供资产列表、表单和详情。

**验收：** 脚本必须填写前置条件、执行方式和回滚说明；版本不可覆盖；支持系统、架构、环境、风险和标签筛选。

**依赖：** 模块 5。

### 模块 7：服务器档案与敏感凭据（已完成）

**范围：** 服务器档案 CRUD、项目/环境归属、凭据加密保存、单独解密查看与审计；前端默认脱敏展示并提供明确的查看动作。

**验收：** 数据库无凭据明文；普通成员不可查看；仅项目负责人和系统管理员可解密；查看、编辑均审计；接口日志不含凭据。

**依赖：** 项目权限基础；加密主密钥通过环境变量提供。

### 模块 8：环境指纹与部署方案（已完成）

**范围：** 环境指纹、部署方案、方案步骤和资产编排；前端提供结构化编辑和详情展示。

**验收：** 方案关联明确的资产版本和执行顺序；包含前置条件、部署步骤、回滚步骤及风险提示；环境指纹可规范化检索。

**依赖：** 模块 6、7。

### 模块 9：部署记录、成功基线与相似环境检索（已完成）

**范围：** 记录实际服务器、方案、资产版本、执行人与结果；成功记录可形成基线；按环境特征计算可解释的相似结果；前端提供执行记录和历史方案检索。

**验收：** 只有成功记录可标记基线；历史快照不受后续方案修改影响；检索结果展示匹配项和差异项；仍受项目权限控制。

**依赖：** 模块 6、7、8。

### 模块 10：审计查询、部署构建与第一期验收

**范围：** 管理员审计日志查询；按 Plane 交互参考统一全局工作区、项目侧边栏、模块导航和列表/详情布局；补齐空、加载和错误状态；完善 Docker 构建/运行配置、环境变量模板及第一期操作说明；执行前后端、数据库迁移和核心链路验收。

**验收：**

- 可完成“创建项目 → 维护成员 → 上传版本化资产 → 关联服务器和环境 → 创建方案 → 记录成功部署 → 检索相似环境方案”。
- 无权用户不能查看项目资料、下载文件或读取凭据。
- 后端全量测试和打包通过；前端类型检查、测试和生产构建通过。
- Docker Compose 配置可验证，真实生产部署和备份恢复演练若受当前环境限制则明确记录。

**依赖：** 前述全部模块。

## 前后端同步策略

1. 模块 2 先完成成员 API 契约与测试，模块 3 立即消费该契约。
2. 模块 4 起每个业务模块都按“迁移与 API → 前端类型/客户端 → 页面交互 → 联合测试”完成，不再堆到最后统一做前端。
3. 共用的项目选择、分页、错误处理、权限判断和文件上传状态只在出现真实复用需求后提取，避免提前抽象。
4. 每完成一个模块更新 `PROGRESS.md`；每 2～3 个模块执行一次前后端全量检查，模块 10 执行最终验收。

## 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 2GB 文件无法由普通请求稳定上传 | 固定大小分片、流式写盘、完成阶段校验，不在内存聚合 |
| 文件元数据和物理文件不一致 | 临时区写入，完成校验后原子移动；失败任务可清理 |
| 凭据泄露 | AES-GCM 等认证加密、密钥环境变量、响应脱敏、查看单独审计 |
| 项目资源越权 | 功能权限与项目成员权限双层校验，集成测试覆盖外部用户 |
| 方案变更破坏历史 | 部署记录保存方案及资产版本快照，不只保存当前外键状态 |
| 相似检索结果难解释 | 返回匹配字段、差异字段和得分，不做不可解释的黑盒推荐 |
| 连续开发导致回归范围扩大 | 模块级测试后立即回归，保持小迁移、小接口和小页面 |

## 当前默认产品决策

- 项目成员普通管理接口不能创建、修改或删除 `OWNER`；负责人交接作为后续显式接口处理。
- 项目 `MANAGER` 可以维护 `MANAGER`、`MEMBER`、`VIEWER`，但不能操作 OWNER。
- 删除普通成员为幂等操作；重复添加返回冲突。
- 第一阶段文件默认使用本地受控存储，接口保留未来切换 S3 兼容存储的边界，但本期不提前实现多存储适配框架。
- 前端保持现有蓝色内部管理系统风格，不引入新的 UI 框架或全局状态库。
- 项目交互逐步向 Plane 式工作区和项目内导航演进，但不复制 Plane 源码或品牌资源。
