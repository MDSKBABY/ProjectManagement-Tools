# 开发规范

## 渐进式开发

每次只开发一个模块。模块开始前明确目标、输入输出、涉及文件、风险和验收标准；模块完成后独立运行相关测试，再等待用户确认是否进入下一模块。

禁止把多个业务模块混在同一次修改中，也不能用最终整体验收代替模块测试。

## 代码注释

注释用于解释“为什么这样设计”和“必须守住什么约束”，而不是逐行翻译代码。

必须添加注释的场景：

- Controller、Service 等对外提供能力的类和公共方法。
- 认证、授权、密码、会话、CSRF 等安全边界。
- 事务范围、幂等规则、审计要求和不可省略的业务保护。
- 不直观的 SQL、算法、兼容逻辑和临时限制。
- 配置项的安全默认值及生产环境差异。

不应添加的注释：

- 重复方法名或单行代码含义的注释。
- 已经失效但未同步更新的历史说明。
- 被注释掉的旧代码。
- 包含密码、Token、连接凭据或个人敏感信息的注释。

修改代码时必须同步检查附近注释是否仍然准确。错误注释比没有注释风险更高。

## 模块验收记录

每个模块完成后在根目录 `PROGRESS.md` 记录：

- 完成内容和未包含范围。
- 实际执行的测试命令与结果。
- 已知风险和下一模块。
- 新会话需要优先读取的入口文件。

## Git 与安全

- 未经用户明确要求，不创建提交或推送远程仓库。
- `.env`、密码、密钥和 Token 不得进入版本库。
- Flyway 已执行的迁移文件不可修改，数据库变化必须新增迁移。
- 不得以关闭 CSRF、权限校验或输入校验的方式解决开发问题。
